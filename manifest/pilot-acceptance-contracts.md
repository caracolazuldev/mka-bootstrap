# Pilot Acceptance Contracts (4-6 Week Prototype Window)

This document defines acceptance contracts for the three selected pilots. Each pilot must validate both MKA artifact usage and APT packaging viability for internal collaborators.

## Contract Template (Required Evidence)

For each pilot, maintain evidence entries covering:

- Scope statement
- MKA artifacts used
- APT packaging validation path
- Containerized test context
- Evidence links in missives
- Open issues / friction notes
- Acceptance decision

## Pilot 1: Product Manager & Implementation Manager (Agentic MKA)

### Scope statement
Implement an agentic capability that separates Product governance and Implementation execution while interleaving via roadmap state.

### MKA artifacts used
- Manifest requirement entry
- Roadmap milestone state transitions
- Approach notes for implementation sequencing
- Missives for stakeholder-facing outcomes

### APT packaging validation path
- Produce a prototype package descriptor for PM/IM function assets.
- Define package dependency notes for internal install context.
- Verify install/use in a containerized workspace.

### Containerized test context
- Internal collaborator test container with mounted project source.

### Evidence links in missives
- To be recorded during pilot execution.

### Open issues / friction notes
- To be recorded during pilot execution.

### Acceptance decision
- Pending.

## Pilot 2: Google Collaboration Suite (Docs/Sheets/Slides/Drive/Calendar/Tasks)

### Scope statement
Implement collaboration contexts and capability boundaries for human-agent interaction across Google collaboration tools, using markdown-sync utilities as foundations.

### MKA artifacts used
- Manifest capability constraints
- Architecture context model for collaboration objects and lifecycle
- Approach workflow mappings to markdown-sync utilities
- Missives for operational outcomes and decisions

### APT packaging validation path
- Prepare at least one collaboration capability bundle with dependency metadata.
- Validate reproducible setup path for internal testing.
- Confirm package-style install instructions in containerized environment.

### Containerized test context
